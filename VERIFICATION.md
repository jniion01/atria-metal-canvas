# Проверка экспортного комплекта

Основа: опубликованная ревизия `d36231c57ec3c4db447eb7dbb5b20e4bed24e166`.

## Сборка и упаковка

- Чистая установка зависимостей через `npm ci`.
- `npm test`: размеры, сборка, гибка, жесты, кадрирование и AR-экспорт.
- `npm run build`: production-сборка и дополнительная проверка ссылок между отложенными модулями.
- Workflow GitHub Actions разобран YAML-парсером; публикация настроена из `dist/`.
- Ссылки на ресурсы относительные: сайт проверяется по `/atria-metal-canvas/`, как на GitHub Pages.
- В ZIP входят исходники, зафиксированные зависимости, готовый `dist/`, инструкция и workflow. Зависимости `node_modules`, служебные папки хостинга, история Git и браузерные профили исключены.
- Архив распакован в отдельную папку. Проверены CRC ZIP и SHA-256 каждого файла, затем именно распакованный `dist/` запущен под `/atria-metal-canvas/`. Повторный браузерный прогон прошёл без необработанных JavaScript-ошибок и пропавших ресурсов. Контрольные суммы файлов входят в `CHECKSUMS.sha256`.

## Оптимизация

Стартовый набор JavaScript и CSS для основного 3D-просмотра уменьшен с **1 964 596 до 1 756 170 байт (−10,61%)** до HTTP-сжатия. Это измерение размера ресурсов, а не обещание такого же сокращения времени загрузки. Модули AR-экспорта, model-viewer и трассировки загружаются по запросу. Файлы геометрии, текстур, жестов и кадрирования побайтово совпадают с исходной ревизией; версии зависимостей также сохранены.

Дополнительно изменены только `PhotoRenderer.js` и `RenderEngine.jsx`: до появления действительного изображения остаётся обычный предпросмотр. Непустота проверяется маской 64 × 64 один раз после остановки камеры. При полностью прозрачном результате трассировка отключается, её ресурсы освобождаются, а модель продолжает отображаться в обычном режиме. Ложный статус успешного расчёта больше не показывается.

## Проверенные сценарии

- Настоящий WebGL в Chrome: desktop 1440 × 900, мобильные размеры 390 × 844, 390 × 744 и 320 × 568.
- Профильная рама и гнутый лист, большой формат, текстиль и гравировка.
- Разборка и возврат к собранной картине, сброс ракурса, полноэкранный просмотр.
- Масштабирование двумя касаниями внутри сцены: масштаб страницы остаётся равен 1.
- Сохранение приближения и направления камеры при изменении размеров окна.
- Отложенные AR- и фото-модули не запрашиваются до открытия соответствующего режима.
- Во время сценариев проверяются необработанные JavaScript-ошибки и ответы 404 на ресурсы.
- Фоторежим обеих конструкций проверен в Chrome со SwiftShader до появления прогрессивного изображения (4+ отсчёта), со скриншотами и проверкой цветных пикселей картины. Полный расчёт 96 отсчётов на этом программном backend не использовался как замер скорости реального устройства.
- На штатном графическом backend тестовой среды воспроизведён пустой результат трассировки. Защита срабатывает для обеих конструкций: обычная картина остаётся видна, вместо ложного успеха появляется сообщение о переходе на быстрый рендер. Проверены отсутствие ошибок JavaScript и загрузка всех файлов под адресом репозитория.

## Проверки данных модели

- 8 рисунков × 2 формата для гнутой конструкции: перемычки, прорези и отсутствие пересечений бортов.
- 96 вариантов кадрирования и 96 000 проекций точек ограничивающей сферы.
- Реальный OrbitControls: повторные pinch-жесты, фиксированный центр, приближение до 65 мм для A3.
- Четыре сборки настоящей R3F-модели экспортированы в GLB и USDZ. Проверены физические размеры в метрах, металлические материалы, текстиль, карты гравировки и неизменность исходной геометрии.
- Проверена ветка iOS: готовый USDZ, правильный MIME-тип, ссылка `rel="ar"` с изображением и запретом масштабирования. Web AR-модель также успешно загружается.

## Границы проверки

Эмуляция размеров и User-Agent не заменяет физический iPhone. Открытие системного Quick Look, разрешение камеры, поиск реальной стены и точность трекинга в комнате требуют проверки на устройстве. Изображение в Quick Look зависит от системного освещения AR. Обычный desktop не обязан поддерживать AR: доступность определяется возможностями устройства.

Workflow подготовлен и проверен локально; запуск на GitHub произойдёт после загрузки в ваш репозиторий и выбора **Settings → Pages → Source → GitHub Actions**. Публикация из этого архива автоматически здесь не выполнялась.
